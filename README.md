> Полнофункциональная система управления складом, заказами и поставками для ресторана. Собрана для Umirhack.

## ✨ Возможности

### 📦 Управление складом
- Учёт продуктов с весовыми, объёмными и штучными единицами (кг/г, л/мл, шт)
- Партийный учёт с датами прихода и окончания срока годности (FEFO)
- Ручная корректировка остатков, изменение срока годности, списание партий
- Автоматическое списание просрочки одной кнопкой
- Фильтрация по состоянию: норма / внимание / критично / просрочено

### 🍽️ Рецепты и блюда
- Справочник блюд с ингредиентами и нормами закладки
- Автоматический расчёт доступности блюд по остаткам на складе
- Ручной стоп-лист: снятие блюд с продажи по решению персонала

### 🛒 Заказы и кассовая работа
- Оформление заказов с учётом остатков (списание по FEFO)
- **Кастомизация блюд на этапе готовки** — добавление или удаление ингредиентов к конкретному блюду в заказе
- Автоматический пересчёт итога чека при кастомизации
- Смена статусов: новый → готовится → подан → выполнен / отменён
- Отмена заказа с возвратом продуктов на склад (только админ)

### 🚚 Поставки и автозаказ
- Приёмка поставок с формированием партий и автоматическим расчётом срока годности
- **График поставок** — настройка периодичности и плеча доставки для каждого продукта
- Расчёт потребности: `средний расход × (период + плечо) + минимальный остаток − текущий запас`
- Формирование и оформление автозаказа в одну кнопку
- Прогноз покрытия запасом в днях и цветовая индикация уровня

### 🏷️ Акции и скидки
- **4 типа акций** с автоматическим применением максимальной подходящей:
  - 🎂 День рождения — скидка имениннику
  - 💰 Минимальная сумма чека
  - 🕐 Счастливые часы (часовой интервал)
  - ⏳ Истекает срок годности (скидка пропорционально доле «рисковых» продуктов в чеке)
- Проверка скидок для произвольной суммы чека прямо на фронтенде

### 🔥 Горячие предложения
- Ранжирование блюд по приоритету реализации (FEFO-скор)
- Учёт близости сроков годности и доли «рисковых» продуктов в рецепте
- Рекомендации по быстрому обороту скоропортящегося сырья

### 📊 Аналитика и журналы
- Расширенная аналитика на основе системных логов и истории транзакций
- Ключевые метрики: конверсия заказов, объём списаний, отказы по дефициту
- Превентивный прогноз дефицита и стоп-листа
- Лента критических инцидентов (отказы заказов, акты списания)
- Продвинутый журнал событий с фильтрацией и поиском

### 🔐 Авторизация и роли
- Двухуровневая система: **admin** (полный доступ) и **staff** (ограниченный)
- Токенизированная авторизация (Bearer token) с TTL сессии 12 часов
- Управление пользователями через админ-панель

### 🎬 Демо-режим
- Автоматическая имитация работы ресторана: заказы, поставки, списания, авторизации, стоп-лист, инвентаризация, кастомизации
- Независимая настройка интервалов для каждого типа действия
- Точечный запуск отдельных действий по требованию

## 🏗️ Архитектура

- **Бэкенд** — Go 1.21, stdlib `net/http`, `sync.RWMutex` для потокобезопасности
- **Фронтенд** — чистый JavaScript (ES6), Tailwind CSS (CDN), FontAwesome, Google Fonts
- **Хранение** — in-memory (оперативная память), данные инициализируются при запуске
- **Коммуникация** — REST API (JSON) + Server-Sent Events (SSE) для real-time-уведомлений

## 🚀 Быстрый старт

### Предварительные требования

- **Go** 1.21+
- Любой современный браузер (Chrome, Firefox, Edge)

### Запуск

```bash
# Сборка бинарника
cd backend
go build -o umirhack-server main.go

# Запуск сервера (по умолчанию :8080)
./umirhack-server -static frontend
```

Или из корня репозитория:

```bash
cd backend
go run main.go -static ../frontend
```

Сервер откроет интерфейс по адресу: **http://localhost:8080**

### Вход в систему

| Логин  | Пароль | Роль     |
|--------|--------|----------|
| admin  | admin  | Администратор |
| staff  | staff  | Сотрудник |

## 📦 Развёртывание

### Сборка бинарников

```bash
# Linux
cd backend && go build -o umirhack-server-linux main.go

# Windows (из-под Linux через кросс-компиляцию)
GOOS=windows GOARCH=amd64 go build -o umirhack-server.exe main.go
```

### systemd-сервис

```ini
# /etc/systemd/system/borsch.service
[Unit]
Description=BORSCH Restaurant System
After=network.target

[Service]
ExecStart=/opt/borsch/umirhack-server -static /opt/borsch/frontend
WorkingDirectory=/opt/borsch
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now borsch
```

## 👥 Пользователи и роли

### admin
Полный доступ ко всем функциям:
- Управление продуктами, блюдами, поставками
- Стоп-лист, кастомизация, отмена заказов
- Настройка графиков поставок и акций
- Управление пользователями
- Демо-режим (настройка интервалов)
- Инвентаризация, изменение сроков, удаление партий

### staff
Ограниченный доступ:
- Создание и управление заказами
- Кастомизация блюд в заказе
- Стоп-лист (снятие/возврат блюд)
- Приёмка поставок, списание партий
- Просмотр аналитики и горячих предложений
- Запуск демо-режима (без настройки интервалов)

## 🎬 Демо-режим

Демо-режим автоматически имитирует работу ресторана:

| Действие        | Что происходит                           |
|-----------------|------------------------------------------|
| 🛒 Заказы       | Гости оформляют блюда, продукты списываются |
| 🚚 Поставки     | На склад приходят новые партии           |
| 🗑 Списания      | Порча и авто-списание просрочки          |
| 🔐 Авторизации  | Входы персонала в систему                |
| 🚫 Стоп-лист    | Блюда снимаются/возвращаются             |
| ✏️ Инвентаризация | Ручные корректировки остатков           |

**Управление:** кнопка «Демонстрация» в сайдбаре — быстрый старт/стоп, долгое нажатие — настройка интервалов.

## 🧮 Логика расчётов

### Форматирование единиц
- **Вес:** `1.5 кг` → `1.50 кг`, `250 г` → `250 г`
- **Объём:** `2.5 л` → `2.50 л`, `400 мл` → `400 мл`
- **Штуки:** целые числа (`12 шт`)

### FEFO (First Expire, First Out)
При создании заказа продукты списываются из партий с ближайшим сроком годности.

### Автозаказ
```
Потребность = Средний_расход_в_день × (Период_поставок + Плечо_доставки)
            + Минимальный_неснижаемый_остаток − Текущий_запас
```

### Акции
Система проверяет все активные акции и применяет **максимальную подходящую**:
- `birthday` — всегда доступна
- `min_sum` — при превышении порога чека
- `happy_hour` — в указанный часовой интервал
- `near_expiry` — пропорционально доле ингредиентов с истекающим сроком в составе заказа

### Кастомизация
- **Добавление** ингредиента → добавление к чеку по розничной цене (себестоимость × 2), списание со склада по FEFO
- **Удаление** ингредиента → возврат денег, продукт возвращается в самую раннюю партию
